1. ЦЕЛЬ И ГРАНИЦЫ
Внедрение этапа 2 (карта, добавление, карточки, замечания) и поддержка реальной общей базы на BotHost вместо localStorage. Создание админ-панели и потоковый импорт Excel/CSV вынесены в последующие этапы. Авторизация MAX используется из уже существующего v0.4.4. Код разрабатывался отдельно от main, до слияния рабочий BotHost не перезапускался.

2. СТРУКТУРА БАЗЫ
- Перенесены проверенные файлы этапа v0.5.0: inventory_model.py, inventory/catalog.json, inventory/schema_v050.sql, ARCHITECTURE.md, import_template_v1.csv и тесты.
- Используется отдельная SQLite-база DATA_DIR/inventory.sqlite3. Исходная база DATA_DIR/trees.sqlite3 не удаляется и не изменяется; при запуске старые записи копируются идемпотентно с сохранением ID, автора, времени, описания и доступных фото.
- Подготовлены таблицы objects, basic, expert, area_details, notes, photos, audit, import_batches. Технические экспертные поля и импортный журнал готовы как основа, но пока не имеют полного административного интерфейса.
- Поля наблюдения (объект, координаты или GeoJSON, порода, примерная высота, диаметр, видимое состояние, повреждения, дата и комментарий) отделены от подтверждения объекта и замечаний.

3. СЕРВЕР BOTHost
- Создан inventory_api.py. Публичные GET /api/v2/objects и GET /api/v2/objects/{id} отображают все предложенные и подтверждённые объекты.
- POST /api/v2/objects создаёт дерево/куст после входа; создание площадного GeoJSON объекта доступно только модератору и администратору. Клиент не может подменить автора или статус запроса.
- PATCH /api/v2/objects/{id} проверяет серверные права; собственные неподтверждённые точки пользователя — только первые 168 часов; модератор — любые предложенные точки и свои площадные объекты; администратор — все точки и площади.
- POST /api/v2/objects/{id}/confirm подтверждает предложенную точку для роли moderator/admin; подтверждённый объект сохраняет статус после последующих изменений.
- POST /api/v2/objects/{id}/notes создаёт замечания любым зарегистрированным участником; редактировать дерево это не позволяет. Закрытие — отдельный endpoint .../notes/{note_id}/close, только модератор/администратор, с результатом проверки.
- Публичный признак needs_clarification строится по открытым замечаниям и НЕ меняет confirmation_status. Добавлены ограничения на частоту повторных комментариев (не чаще раза в минуту на объект, не более 20 за 24 часа).
- Фотографии сохраняются отдельно в /app/data/photos; JPG, PNG, WebP по проверке сигнатуры, до 5 МБ и максимум 8 на объект. Права загрузки проверяются сервером.
- app.py подключает новое API, разрешает CORS PATCH для GitHub Pages, отдаёт /ui и показывает версию 0.6.0 в /api/health.
- Авторизация MAX / логин/пароль не заменялась, только добавлено событие об изменении сессии для обновления интерфейса.

4. ФРОНТЕНД
- index.html полностью обновлён под карту v0.6.0. Мобильная форма создания дерева/кустарника, выбранная точка на карте, фотографии, комментарий, наблюдение.
- ui/style.css, ui/map.js: отображение серых/зелёных деревьев, голубых кустарников, красных индикаторов замечаний. Сохранена обязательная атрибуция OpenStreetMap, префикс Leaflet скрыт.
- Карточка объекта показывает характеристики, дату наблюдения, статус подтверждения, фотографии, историю замечаний, а для авторизованных — форму «Требует уточнения».
- Для модератора/администратора — подтверждение точки и создание полигонов газонов, цветников и природных сообществ из точек карты. Администратор редактирует и подтверждённые точки; модератор — только неподтверждённые точки и собственные полигоны.
- Все чтение и запись реальных объектов идут через API BotHost. Существующие localStorage демо-деревья не удаляются и показываются отдельными локальными маркерами; они не станут общими без повторного добавления.
- Новый интерфейс не показывает сохраняемые в браузере объекты как общедоступные, если сервер недоступен; вместо этого отображается явная ошибка подключения.
- При смене точки редактируемого растения сохраняются введённые значения формы.
