VdkTree0004 — Авторизация через MAX и создание логина и пароля
Дата: 05.11.2026
Версия: v0.4.0
Репозиторий: urbanvdk-byte/VdkTree

1. Цель
Реализовать первичную регистрацию исключительно через одобренный бот MAX и позволить уже зарегистрированным пользователям по желанию установить собственный логин/пароль. Почтовую авторизацию не реализовывать. Сервер готовится к BotHost, интерфейс остаётся на GitHub Pages.

2. Изменения
- auth_backend.py: /api/auth/max — серверная проверка HMAC-SHA256 initData MAX согласно dev.max.ru; проверяются подпись, наличие уникальных ключей, возраст данных (15 мин), подписанный id пользователя.
- /api/auth/password — вход по заранее созданным логину/паролю, без саморегистрации.
- /api/auth/credentials — создать логин и пароль можно из сессии, возникшей после MAX. Повторная первичная установка заблокирована.
- /api/auth/me и /api/auth/logout — получение профиля и завершение сессии.
- SQLite auth.sqlite3 в DATA_DIR (BotHost /app/data): пользователи, сессии, ограничения попыток входа.
- Хеширование паролей hashlib.scrypt с индивидуальной случайной солью; случайные session tokens с хранением только SHA-256 токена в БД. Длительность сессии — 7 дней.
- auth/client.js, auth/auth.css, auth/config.js: кнопка входа в пользовательском интерфейсе, автоматическое распознавание MAX Bridge, предложение создать логин/пароль после первого входа, вход в браузере по созданным данным; сохранение токена только в sessionStorage.
- app.py: версия 0.4.0, CORS для GitHub Pages и BotHost, подключение auth API, защита POST /api/trees аутентификацией, запись author_id для новых деревьев, обновление старой SQLite-схемы без удаления существующих деревьев, выдача файлов /auth/*, запуск uvicorn на 0.0.0.0:$PORT (по умолчанию 3000).
- index.html: версия v0.4.0 справа вверху; подключены MAX Bridge и пользовательский модуль авторизации. Файлы Supabase больше не загружаются в браузере.
- BOTHOST.md — настройки BotHost и подключение мини-приложения MAX.
- tests/test_auth.py и .github/workflows/auth-tests.yml — автоматические проверки подписи MAX, подмены/просрочки/дубликатов, создания и повторной блокировки логина, входа паролем, защиты API, ограничений попыток входа, CORS; контроль компиляции Python и синтаксиса JavaScript.

3. Ошибки и решения
- Изучена официальная спецификация MAX. Обычный id из JavaScript не подтверждает личность. Реализована серверная проверка подписанной строки initData с HMAC ключом на основе BOT_TOKEN.
- Ранний вариант счётчика неверных паролей откатывался из-за HTTP 401 внутри транзакции. Исправлено явным db.commit() перед отказом и закрытием SQLite-соединения через contextmanager.
- BotHost требует, чтобы веб-сервер слушал 0.0.0.0 на назначенном PORT. Добавлен запуск uvicorn непосредственно из app.py.
- В прежнем app.py POST /api/trees был доступен анонимно. Теперь для создания дерева требуется действующая сессия.
- Ранее подключённый, но не настроенный Supabase удалён из загрузки index.html. Демо-сохранение деревьев в localStorage пока сохранено и не подменяет общую базу.

- В настройках одобренного бота MAX привязать мини-приложение https://urbanvdk-byte.github.io/VdkTree/.
