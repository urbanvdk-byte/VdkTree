1. Проблема и цель
В версии v0.7.0 у модератора были отдельные кнопки для подтверждения и закрытия замечаний в карточке. Не существовало единой очереди предложенных растений и замечаний, наглядных счётчиков, фильтров и истории решений. Для общественной карты Владивостока необходимо централизованное рабочее место, не раскрывающее административный backend обычному модератору.

2. Изменения Python API
Создан moderation_api.py с префиксом /api/v2/moderation. GET /queue возвращает порции до 100 объектов с фильтрами all/pending/notes и tree/shrub/area, количеством предложенных объектов и открытых замечаний. GET /objects/{id}/history выдаёт историю изменения объекта (inventory_audit), авторов и содержание решений. POST /objects/{id}/review принимает confirm либо request_changes. При confirm точка становится confirmed, подтверждение и исполнитель фиксируются в inventory_objects и аудите. При request_changes статус растения НЕ меняется, создаётся отдельная открытая запись inventory_clarifications и аудит. Для запроса уточнения требуется комментарий минимум 3 символа. Действия выполняются в транзакции с блокировкой строки FOR UPDATE.
Все модераторские маршруты проверяют роль moderator/admin через current_session на сервере. Неподтверждённую точку может редактировать модератор, подтверждённую — только администратор. Правила чужих полигонов оставлены консервативными. Открытые замечания подтверждённого дерева доступны для рассмотрения, не меняя статус.

3. Новый интерфейс
В ui/management.js добавлена плавающая кнопка «🛡️ Модерация», видимая только staff. Создано окно очереди: фильтры, пагинация, счётчики, кнопки «Карточка», «Подтвердить», «На уточнение», «История решений». Связь с существующей картой реализована через window.VdkMap и событие vdktree:card. Модератор может открыть карточку из очереди, редактировать простые поля и закрывать замечания с указанием результата. Подтверждение требует отдельного согласия. Добавлены мобильные стили management-dialog и management-item. index.html подключает новый скрипт; общий индикатор версии в верхнем правом углу итоговой версии показывает v1.0.0.

4. Ошибки и их решение
На этапе проектирования отделили модераторские операции от админских: доступ к импорту оставлен строго admin. Для сохранения отличия уточнения от статуса объекта в API реализована отдельная заметка, а не третий статус. Проверка прав на сервере не заменяется скрытием кнопок в JS. Проблем с работой PostgreSQL по итогам прогонов нового API не осталось.

5. Тесты
tests/test_management.py проверяет запрет доступа анонимным и обычным пользователям (401/403), фильтры очереди, недопустимый размер страницы, обязательность комментария, созданное замечание, независимость подтверждения, историю решений, повторное подтверждение (409) и закрытие заметки. Итоговые CI проверки PostgreSQL, MAX, UI и Docker завершились SUCCESS.

7. Результат и применение
Модераторская панель включена в общий релиз v1.0.0. На BotHost требуется новая сборка Python-сервера из main; новая функциональность не должна считаться проверенной на реальной PostgreSQL BotHost до пользовательской приёмки. Администратор может назначать роли через защищённый SQL-интерфейс PostgreSQL. Новый тег или checkpoint не создавался.
