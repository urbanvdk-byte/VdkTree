VdkTree0007 — Упрощение первого входа через MAX
Дата: 05.11.2026
Версия пользовательского интерфейса: v0.4.2
Репозиторий: urbanvdk-byte/VdkTree, ветка main.

1. ИСХОДНАЯ ПРОБЛЕМА
Пользователь открыл окно «Вход в VdkTree» и не понял, куда нажимать:
главными элементами были пустые поля «Логин» и «Пароль», хотя
первичная регистрация возможна исключительно через одобренного MAX-бота.
В тексте говорилось «откройте VdkTree из мини-приложения MAX» без
пошаговой инструкции и без явного действия.
Скриншот не позволял однозначно определить, был ли сайт запущен
внутри MAX или напрямую из браузера.

2. ЧТО СДЕЛАНО
- auth/client.js:
  * Переорганизован интерфейс неавторизованного посетителя: сначала
    указано «Впервые здесь? Логин и пароль не нужны!».
  * Добавлена пошаговая инструкция: открыть MAX, найти чат с ботом
    «Деревья Владивостока», нажать кнопку «Открыть».
  * Добавлена кнопка «Перейти в MAX». Пока она ведёт на главную страницу
    max.ru, а НЕ сразу в нужный чат; для однокнопочного запуска нужен
    подтверждённый публичный URL бота.
  * Поля логина и пароля для повторного входа скрыты под раскрывающимся
    разделом «У меня уже есть логин и пароль».
  * Добавлена кнопка «Проверить вход через MAX».
  * При отсутствии подписанных стартовых данных показывается явное
    сообщение: необходимо заново открыть мини-приложение кнопкой бота
    в MAX; прямая ссылка на сайт не подтверждает личность.
  * Сохранён автоматический вход по window.WebApp.initData.
  * Дополнительно предусмотрен официальный путь получения подписанных
    WebAppData из URL-фрагмента (в случае недоступности MAX Bridge).
  * Для запуска мини-приложения вызывается window.WebApp.ready,
    если метод доступен.
  * Все данные MAX продолжают проходить серверную проверку подписи,
    никакие initDataUnsafe не используются для аутентификации.
- auth/auth.css:
  * Добавлены стили заметной кнопки перехода в MAX, списка шагов,
    разворачиваемого входа по логину и паролю, сообщений диагностики.
- index.html:
  * В верхнем правом углу версия изменена с v0.4.1 на v0.4.2.
- tests/test_auth_ui.js:
  * Созданы проверки трёх сценариев: браузер без данных MAX;
    автоматический вход через MAX Bridge; подписанные данные из
    URL-фрагмента WebAppData.
- .github/workflows/auth-ui.yml:
  * Создан отдельный GitHub Actions workflow для проверки синтаксиса
    клиентского JavaScript и сценариев первого входа.
- Python API, SQLite, Dockerfile и текущий BotHost не менялись:
  /api/health по-прежнему может сообщать версию backend 0.4.1.
  Установка логина/пароля и MAX-проверка происходят на прежнем API.

3. ОБНАРУЖЕННЫЕ ОШИБКИ, ДИАГНОСТИКА И ИСПРАВЛЕНИЯ
- Первая проверка UI-тестов завершилась ошибкой: упрощённый тестовый
  DOM-макет не реализовал метод dialog.setAttribute. Метод добавлен
  к имитатору элементов; реальный браузерный код работал штатно.
- Вторая проверка обнаружила, что имитатор не умел искать вложенные
  элементы с помощью querySelector на уровне dialog. Добавлен
  поиск через дочернюю панель, аналогичный браузерному.
- Третья проверка выявила неверное утверждение теста: форма создания
  учётных данных находилась во вложенном элементе #vdk-create-credentials,
  а не в outer innerHTML. Тест исправлен на проверку вложенного элемента.
- После этих поправок GitHub Actions:
  «VdkTree MAX onboarding UI tests»
  run 42016860872 — SUCCESS.
  Проверки синтаксиса JS и всех трёх смоделированных сценариев пройдены.
- Реальная авторизация в клиенте MAX пока не подтверждена пользователем;
  тесты используют имитацию ответов сервера, не настоящий токен бота.

5. ДАЛЬНЕЙШИЕ ДЕЙСТВИЯ
- Убедиться, что в панели MAX для бизнеса к одобренному боту
  привязано мини-приложение:
  https://urbanvdk-byte.github.io/VdkTree/
- Открыть чат бота в MAX → «Открыть», подтвердить автоматический вход
  и создание логина/пароля, затем проверить повторный вход в браузере.
- Получить публичную ссылку на конкретного MAX-бота, чтобы заменить
  общий переход max.ru настоящей ссылкой вида
  https://max.ru/<botName>?startapp (без угадывания имени).
- При необходимости посмотреть сообщение диагностики MAX и журналы
  BotHost (без публикации токена, данных подписи или паролей).
- Продолжить разработку в отдельной feature-ветке v0.5.0 после
  окончательного подтверждения авторизации.
