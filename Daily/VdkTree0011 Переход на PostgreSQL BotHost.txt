1. ЗАДАЧА
Пользователь создал для VdkTree базу PostgreSQL в BotHost и добавил в переменные бота секрет DATABASE_URL. Пользователь явно подтвердил, что старые тестовые SQLite-данные переносить не нужно: реальных участников и полезных записей пока нет.
Требовалось подключить PostgreSQL ко всей рабочей системе, а не просто добавить переменную. В прошлой версии MAX-учётные записи хранились в SQLite auth.sqlite3, растения и заметки в SQLite inventory.sqlite3, фотографии — в файловом каталоге контейнера. Так как отдельная база PostgreSQL уже предоставлена, эти механизмы должны быть заменены без смешения источников данных.

2. АРХИТЕКТУРА
- Добавлен pgdb.py. Единственный адрес подключения берётся из DATABASE_URL. Поддерживаются строки postgresql:// и postgres://; при отсутствии корректного адреса приложение явно сообщает о необходимости задать его в BotHost.
- Для PostgreSQL использован psycopg 3 (psycopg[binary]), версия драйвера закреплена диапазоном >=3.2,<4 в requirements.txt.
- Совместимый адаптер подключения сохраняет привычный интерфейс SQL-запросов с параметрами ? и возвращает строки, поддерживающие доступ по имени и индексу.
- Подготовлен inventory/schema_postgres.sql с таблицами inventory_objects, inventory_basic, inventory_expert, inventory_area_details, inventory_clarifications, inventory_photos, inventory_audit, inventory_import_batches.
- В структуру inventory_photos добавлено поле content BYTEA NOT NULL. Фотографии сохраняются непосредственно в БД и не должны исчезать при пересоздании контейнера.
- Исторический проектный SQLite-скрипт inventory/schema_v050.sql сохранён для документации, но в работающем PostgreSQL-сервере он не исполняется.
- SQLite-таблицы и данные не мигрируются. Старые тестовые файлы из /app/data не удалялись — просто перестали использоваться работающим кодом.

3. АВТОРИЗАЦИЯ MAX И ЛОГИН/ПАРОЛЬ
- auth_backend.py переведён с SQLite на PostgreSQL.
- Таблицы users, sessions, login_limits создаются в PostgreSQL автоматически при старте приложения.
- Для login сделан уникальный индекс по lower(login), сохраняющий защиту от дублирования логинов с разным регистром.
- Проверка подписи initData MAX по HMAC-SHA256, проверка времени запуска, случайные токены сессии, SHA-256 хеш токена и scrypt для пароля сохранены.
- Проверка частого перебора паролей и запрет самостоятельной регистрации без MAX сохраняются.
- Обработка UPSERT/ON CONFLICT заменяет прежние SQLite INSERT OR IGNORE / INSERT OR REPLACE.
- Реальный MAX_BOT_TOKEN остаётся только переменной окружения BotHost и никуда не копировался.

4. ОБЪЕКТЫ, ЗАМЕЧАНИЯ И ФОТОГРАФИИ
- inventory_api.py подключается к PostgreSQL и использует отдельную схему PostgreSQL.
- Объекты карты, правила ролей, семидневное редактирование своей предложенной точки, подтверждение, замечания, аудит, площадные объекты сохраняют прежнее API /api/v2/objects.
- Фотографии JPG/PNG/WebP до 5 МБ и до 8 на объект записываются в BYTEA, а не в /app/data/photos. Добавлена блокировка строки объекта FOR UPDATE, чтобы одновременные загрузки не обходили лимит фотографий.
- app.py отдаёт изображения из PostgreSQL по GET /photos/{имя} с заданными MIME-типами. Файлы SVG и произвольные пути не поддерживаются. В заголовке ответа включено X-Content-Type-Options: nosniff.
- app.py удалил старый тестовый SQLite API /api/trees. Основной публичный интерфейс и сценарии регистрации используют актуальный /api/v2/objects.
- /api/health теперь действительно проверяет соединение с PostgreSQL. Ожидаемый результат: {"ok":true,"version":"0.7.0","database":"postgresql"}.
- В index.html справа вверху версия обновлена до v0.7.0.

5. GITHUB ACTIONS И ТЕСТЫ
- .github/workflows/auth-tests.yml запускает PostgreSQL 16 как сервис, устанавливает зависимости и выполняет все pytest-тесты через фиктивный DATABASE_URL.
- .github/workflows/bothost-docker.yml собирает реальный Docker-образ приложения, поднимает PostgreSQL 16, запускает контейнер с тестовой DATABASE_URL и проверяет HTTP /api/health и /api/v2/objects.
- tests/test_auth.py переписан для PostgreSQL и новых маршрутов общего API.
- tests/test_inventory_api.py проверяет реальное хранение PNG в PostgreSQL и её получение через HTTP после нового обращения к базе; проверяет роли и доступ.
- tests/test_map_ui.js обновлён с версии v0.6.0 на v0.7.0.
- На готовом кандидате: 24 pytest-теста PASSED, дополнительно 17 subtests PASSED. Проверка Docker с PostgreSQL — SUCCESS; проверки клиентского MAX и карты — SUCCESS.
- Все тесты используют тестовые учётные данные, не настоящую базу пользователя.

6. ОШИБКИ И РЕШЕНИЯ
- При первоначальной проверке PostgreSQL возник TypeError: 'NoneType' object is not iterable в функции hybrid_row: при SQL-команде CREATE TABLE библиотека psycopg передавала cursor.description=None. Исправлено безопасной обработкой отсутствующего описания столбцов.
- После этого при открытии карточки растения PostgreSQL сообщил IndeterminateDatatype: could not determine data type of parameter $5. В запросе к списку объектов фильтр проверял IS NULL над параметром без заданного типа. Добавлено явное приведение ?::text.
- Статический тест интерфейса сначала ждал версию v0.6.0, хотя интерфейс уже v0.7.0. Его версия обновлена.
- После всех исправлений полноценные PostgreSQL-тесты прошли успешно.
- Это тестовый стенд GitHub Actions. Реальный BotHost подтвердит подключение к своей базе только после обновления приложения из основной ветки и проверки домена.
