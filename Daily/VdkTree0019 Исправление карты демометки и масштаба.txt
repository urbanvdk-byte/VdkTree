VdkTree0019 — Исправление карты, демометки и масштаба
Дата: 08.11.2026
Репозиторий: urbanvdk-byte/VdkTree
Версия: v1.1.1
Ветка: fix/v111-map-navigation-zoom-cache
PR: https://github.com/urbanvdk-byte/VdkTree/pull/9

1. ПРИЧИНА И ЗАДАЧИ
После выпуска v1.1.0 пользователь сообщил о трёх проблемах:
(1) При переходе из реестра по ссылке «← Карта» вместо карты открывался JSON-ответ {"detail":"Not Found"}.
(2) На карте оставалась «Локальная демозапись», хотя ещё в v1.1.0 было убрано её рисование.
(3) Элементы увеличения/уменьшения масштаба Leaflet были закрыты верхней формой фильтра. Пользователь приложил скриншот, где верхний фильтр перекрывает левую верхнюю часть карты.
Поставлена цель исправить всё сразу без изменения реальных объектов и MAX-авторизации.

2. ДИАГНОСТИКА ПО РЕПОЗИТОРИЮ
Файл registry.html содержал относительную ссылку ./index.html, а FastAPI app.py обслуживал HTML карты лишь по маршруту GET /. Из-за этого BotHost GET /index.html возвращал 404 с телом {"detail":"Not Found"}. На GitHub Pages, где index.html физически есть, ошибка не воспроизводилась. Причина подтверждена кодом.
Файл ui/map.js, опубликованный в v1.1.0, НЕ содержал ни текста «Локальная демозапись», ни кода её отображения. В более ранней версии он выполнял чтение localStorage.getItem("vdktree-demo-v020") и создавал жёлтые пунктирные точки, не связанные с PostgreSQL. Поскольку пользователь продолжал их видеть, наиболее вероятное объяснение — старый HTML/JS браузера либо ещё не обновлённый BotHost. Веб-запросы к живому BotHost из инструментов не позволили подтвердить его фактическую текущую версию. Причина на конкретном клиентском устройстве не установлена окончательно; реализована защита от обоих вариантов устаревшего интерфейса.
Лист ui/style.css и настройка L.map в ui/map.js не меняли положение встроенного zoomControl. По умолчанию Leaflet размещал его в левом верхнем углу карты. Верхний фильтр отображался поверх него из-за абсолютного позиционирования и более высокого z-index.

3. ИСПРАВЛЕНИЕ НАВИГАЦИИ
В registry.html ссылка назад заменена на ./?v=1.1.1. Это корректный относительный адрес в двух вариантах публикации:
- GitHub Pages: https://urbanvdk-byte.github.io/VdkTree/?v=1.1.1
- BotHost: https://vdktree.bothost.tech/?v=1.1.1
В app.py маршрут GET /index.html добавлен как алиас GET /. Даже если где-то останется старый адрес, BotHost должен отдавать карту с кодом 200 вместо HTTP 404. GET /registry и /registry.html сохранены.
Для HTML страниц app.py настроен HTTP-заголовок Cache-Control: no-store, must-revalidate, препятствующий долгому сохранению старого HTML на BotHost. Backend health /api/health теперь возвращает version=1.1.1.

4. УСТРАНЕНИЕ ЛОКАЛЬНЫХ ДЕМОМЕТОК И КЕША
В index.html и registry.html собственные CSS и JS подключаются с параметром ?v=1.1.1: auth/config.js, auth/client.js, ui/map.js, ui/management.js, ui/style.css, auth/auth.css, ui/registry.js, ui/registry.css. Это меняет URL статических ресурсов и заставляет обновлённую страницу запрашивать не старый JS из кеша v1.1.0.
В ui/map.js добавлен безопасный перенос старого браузерного ключа:
- Если localStorage["vdktree-demo-v020"] существует, его содержимое сначала записывается в локальный ключ vdktree-local-demo-archive-v111.
- После чтения архива и проверки, что значение в точности совпадает, старый ключ удаляется.
- Если запись не удалась, данные сохраняются в прежнем ключе, управление картой не прерывается.
- Повторное открытие карты идемпотентно: если старого ключа нет, код ничего не делает.
- В пределах этого исправления архив никуда не выгружается, не передаётся на сервер и не изменяет данные PostgreSQL.
Сам render() не содержит старого локального слоя: отображаются только объекты из GET /api/v2/objects. В CSS удалён стиль .vdk-marker.local, связанный только со старой демоверсией.
Важно: новые версии ресурсов решают проблему лишь после открытия пользователем обновлённого HTML. Необновлённый BotHost или старая вкладка всё ещё могут показывать прежний JS до перезагрузки; это ограничение клиентского кеша и процедуры публикации.

5. КНОПКИ МАСШТАБА
Leaflet инициализируется как L.map("map",{preferCanvas:true,zoomControl:false}) с последующим L.control.zoom({position:"bottomleft"}).addTo(map). То есть встроенный top-left контрол выключен, новый создан в левом нижнем углу.
В ui/style.css установлены отступы слева 12 px и снизу 22 px, увеличен размер кнопок до 35x35 px, применена компактная рамка. Верхний фильтр и кнопка «Я здесь» не изменялись и не должны перекрывать контрол масштаба. На малом экране масштаб остаётся доступен внизу слева.

6. СИНХРОНИЗАЦИЯ ВЕРСИИ И ДОКУМЕНТАЦИЯ
В app.py и /api/health — версия 1.1.1. В верхнем правом углу карты (index.html) и реестра (registry.html) — v1.1.1. Сервисные ссылки на новые HTML-сборки содержат v=1.1.1.
Обновлён BOTHOST.md, создан подробный inventory/MAP_FIX_V111.md с причинами, проверками и инструкцией обновления BotHost. Изменение прав пользователей, сохранение сессий или структуры БД НЕ выполнялось.

7. ТЕСТЫ И ИСПРАВЛЕННЫЕ ОШИБКИ
tests/test_map_ui.js проверяет:
- версию карты, свежую ссылку на реестр и версионные JS/CSS;
- перенос zoomControl в bottomleft и CSS-правило отступа;
- наличие безопасного архива legacyKey, удаление прежнего ключа только после копирования;
- отсутствие в текущем скрипте текста и рендеринга «Локальная демозапись».
tests/test_registry_ui.js проверяет:
- ссылку ./?v=1.1.1 вместо ./index.html;
- новую версию ресурсов и защищённый переход на карту с двух доменов.
tests/test_users_ui.js изменён только для ожидания верхнего правого индикатора v1.1.1.
tests/test_registry.py дополнен серверными интеграционными проверками маршрутов /, /index.html, /registry, заголовков no-store и версии.
.github/workflows/bothost-docker.yml проверяет версию 1.1.1 и запросы /index.html и /registry.html на реально запущенном Docker-контейнере с отдельным PostgreSQL.
Первый запуск Python CI завершился одной ошибкой: в tests/test_registry.py осталось прежнее утверждение assertIn("v1.1.0", r.text) при новом HTML v1.1.1. Приложение при этом работало, Docker smoke test прошёл. Перед исправлением тестовый файл повторно архивирован, ожидание обновлено на v1.1.1, запущен повторный CI. Не исправлялся баг продукта посредством изменения теста: причина падения — устаревшее строковое сравнение номера версии в самом тесте.
По окончании финального CI необходимо отдельно подтвердить живой BotHost уже после обновления, поскольку GitHub Actions не разворачивают контейнер BotHost автоматически.

9. ПУБЛИКАЦИЯ И РУЧНАЯ ПРИЁМКА
После успешных проверок PR №9 объединяется в main; GitHub Pages получает новую версию фронтенда. Для BotHost пользователь отдельно обновляет исходники из main, запускает полную пересборку и перезапуск с прежними DATABASE_URL и MAX_BOT_TOKEN.
Порядок проверки: /api/health 1.1.1, /index.html HTTP 200 вместо 404, /registry -> «← Карта» работает, локальная демозапись не рисуется, +/- снизу слева, реальные растения и права MAX без изменений. При необходимости открыть сайт с параметром ?v=1.1.1 или обновить страницу без кеша.
Проверка фактической загрузки новой версии на пользовательском устройстве требует действий пользователя; автоматический GitHub CI не доказывает, что он уже обновил BotHost.
