1. ПОСТАНОВКА ЗАДАЧИ
Пользователь обнаружил «Локальную демозапись» на карте VdkTree и попросил объяснить её происхождение. Далее распорядился создать независимый от карты интерфейс полного реестра деревьев/кустарников, в котором основные характеристики показываются столбцами и доступны поиск, многофакторная фильтрация и сортировка по разным параметрам по аналогии с каталогом DNS. По нажатию на строку должна открываться подробная профессиональная карточка; администратор должен иметь возможность её изменять. Для каждого дерева/кустарника необходима возможность скачать уже заполненную ведомость из предоставленного регламента.

2. ИССЛЕДОВАНИЕ И ИСТОЧНИКИ
Проверен рабочий код карты ui/map.js. Найдена старая ветка render(), выполняющая JSON.parse(localStorage.getItem("vdktree-demo-v020")||"[]") и создающая метки с title="Локальная демозапись". Эти записи хранятся только на конкретном клиентском устройстве и не являются реальными объектами PostgreSQL. Их видели не все жители, а лишь владелец соответствующего localStorage.
Сайт DNS из запроса https://www.dns-shop.ru/search/?q=коммутатор&category=17a9dc3716404e77 изучен по доступной каталожной странице https://www.dns-shop.ru/catalog/17a9dc3716404e77/kommutatory/ и опубликованным описаниям фасетной сортировки. Прямое программное открытие поиска DNS было ограничено, поэтому не заявляется пиксельное или полное функциональное копирование DNS. Заимствован только общий принцип: группы характеристик, выбор нескольких значений, числовые диапазоны, счётчики, фильтры-чипы, сортировка и динамическая выдача.
Прочитан исходный файл владельца «Регламент инвентаризации, цифрового учета и мониторинга зеленых насаждений города Владивостока.docx», 8 страниц. Главные источники для индивидуальной ведомости: Приложение №2, таблица 2.4 (13 граф, деревья и кустарники), раздел 5 (подеревный учёт), пункт 5.4 (противоэрозионная функция, наклон, асимметрия кроны, эндемики/реликты), пункт 5.5 (шестибалльное санитарное состояние). Пользовательская ведомость является проектной индивидуальной выпиской VdkTree; официальный статус регламента и юридическую силу документа приложение не удостоверяет.

3. УСТРАНЕНИЕ ДЕМОЗАПИСЕЙ
В ui/map.js удалён исключительно код отображения меток, считанных из localStorage ключа vdktree-demo-v020. Содержимое localStorage не удалялось: это предотвращает невосполнимую потерю потенциальных исторических локальных данных. Реальные PostgreSQL объекты inventory_objects, фотографии, связанные замечания и учётные записи не затронуты. Публичная карта продолжает рисовать только настоящие серверные записи из /api/v2/objects.

4. НОВАЯ СТРАНИЦА РЕЕСТРА
Созданы registry.html, ui/registry.css и ui/registry.js. На карте сверху появился прямой переход «📋 Реестр деревьев». На BotHost также можно открыть /registry и /registry.html.
Реестр является отдельной full-width страницей со своим заголовком, версией v1.1.0 справа сверху, панелью фильтров слева и профессиональной таблицей справа. На мобильном фильтры открываются выдвижной панелью. На компьютере таблица может горизонтально прокручиваться; пользователь может показывать или скрывать столбцы. Предпочитаемые колонки сохраняются локально лишь как UI-настройка, в PostgreSQL ничего не меняется.
Основные столбцы: инвентарный номер, тип, русское название, ботанический вид, статус, № участка и растения, высота, диаметр на 1,3 м, возраст, санитарный балл, дата наблюдения. Дополнительные колонки включаются отдельно. Заголовки поддерживают сортировку; в выпадающем списке доступна сортировка по любому параметру реестра.

5. BACKEND И ФИЛЬТРЫ
Создан registry_api.py, APIRouter(prefix=/api/v2/registry). Endpoints:
- GET /meta — серверный справочник всех атрибутов, типов и групп фильтрации.
- GET /facets — текущие варианты многозначных фильтров и подсчёты, пересчитываемые с учётом остальных активных параметров.
- GET / — постраничный список из PostgreSQL с реальным COUNT(*) и сортировкой, по умолчанию 50 строк (лимит API 100).
- GET /{id} — полная характеристика дерева/кустарника, фотографии и замечания.
- PATCH /{id}/inventory-number — отдельное админское изменение инвентарного номера, с проверкой формата и уникальности, аудированием.
- GET /{id}/sheet.xlsx — скачивание заполненной индивидуальной Excel-ведомости 2.4.
Список SQL-выражений ФИЛЬТРОВ и полей сортировки задаётся в FIELDS исходного кода. Ввод посетителя не вставляется в SQL как имя поля, а передаётся только параметрами. Неизвестные параметры и поля, некорректные даты, NaN/inf, неверная сортировка отвергаются HTTP 422.
Реализованы текстовые фильтры «содержит» для названий, видов, дефектов, рекомендаций, номеров, комментариев и источников; диапазоны для высоты, диаметра, возраста, количества, координат, наклона, числа фото, дат; фасеты-галочки для типа растения, статуса, видовой принадлежности, санитарной шкалы, видимого состояния, участка, биогруппы, источника, противоэрозионности, эндемичности и замечаний. Фильтры между полями объединяются AND, внутри одного набора галочек — OR. Поддерживается полный поиск по имени/ID/номерам.
В отличие от API самой карты с лимитом выдачи 5000 точек реестр отдаёт общий COUNT(*) и страницы; большие массивы не требуют единовременной загрузки всех строк.

6. ПРОФЕССИОНАЛЬНАЯ КАРТОЧКА И РЕДАКТИРОВАНИЕ
Нажатие на строку таблицы (или Enter/пробел с клавиатуры) открывает модальную карточку:
- общие учётные сведения, порода, источник и координаты;
- 13 показателей таблицы 2.4, включая шесть санитарных категорий в экспертном поле;
- дополнительные владивостокские признаки из п. 5.4;
- фотографии и замечания, если доступны.
Данные карточки доступны и неавторизованным посетителям. После входа admin видит «Редактировать основные», «Редактировать профессиональные». Изменения обычных сведений сохраняются в существующий PATCH /api/v2/objects/{id}; профессиональные измерения — в действующий PATCH /api/v2/objects/{id}/expert; инвентарный номер — в новый защищённый PATCH. Все эти API сверяют роль на сервере и записывают аудит. Обычные пользователи и модераторы не получают доступа к админскому изменению инвентарного номера.

7. ВЫГРУЗКА ВЕДОМОСТИ
Работает новый публичный endpoint GET /api/v2/registry/{id}/sheet.xlsx. Для каждой точки создаётся отдельный XLSX через уже установленную на BotHost библиотеку openpyxl, без сторонней внешней службы.
На листе «Ведомость 2.4» находятся нормативные 13 граф:
  1 № уч., 2 № био., 3 № раст., 4 Тип нас., 5 Жизн. форма, 6 Вид растения, 7 Кол. (шт), 8 Диам. 1,3 м (см), 9 Выс. (м), 10 Возраст (лет), 11 Сост. Х/У/Н, 12 Категория усыхания / дефекты, 13 Рекомендации.
Заполняются сохранённые в PostgreSQL поля. Если ботанический вид неизвестен, допускается имеющееся общее название без генерации вымышленной латыни. Пустые измерения не подменяются нулём. Формулы из текстов не исполняются: значения, начинающиеся с =,+,-,@, безопасно экранируются.
Важное расхождение исходника регламента: в графе 11 таблицы 2.4 указан Х/У/Н, тогда как в §5.5 отдельно требуется шестибалльная оценка от 1 до 6. В предоставленном документе нет точной таблицы соответствия между этими шкалами. Поэтому ПО НЕ делает недостоверного автоматического вывода категории Х/У/Н; графа 11 не заполняется искусственно. На втором листе «Доп. сведения» печатается реально сохранённый санитарный балл с расшифровкой шкалы из пункта 5.5, дополнительно п. 5.4, координаты, ID, инвентарный номер (если задан) и статус/источник VdkTree.
Файл оформлен с заголовками, печатью A3 альбомной ориентации, переносом строк и обозначением, что это не заверенный муниципальный паспорт. Нормативный инвентарный номер без кадастровых сведений не создаётся.

8. ТЕСТИРОВАНИЕ И ИСПРАВЛЕНИЯ ОШИБОК
Созданы tests/test_registry.py и tests/test_registry_ui.js. Изменены проверки карты и CI для новых маршрутов, новой версии, новой страницы и отсутствия localStorage-демослоя. Проверяются:
- публичный доступ к реестру и полным карточкам;
- составные фильтры по породе, типу, санитарному баллу, высоте, участку, сортировка и переход по страницам;
- фасетные счётчики, неизвестные фильтры, отклонение SQL-небезопасных имён сортировки;
- экспорт XLSX, точное наличие 13 граф, сохранение значений, незаполнение графы Х/У/Н и защиту от Excel-формул;
- права администратора, редактирование инвентарного номера, запрет дубликатов, очистку номера;
- работу /registry в BotHost, ссылку с карты, версию v1.1.0.
Первая серверная проверка дала 2 неуспешных теста при 45 успешных: фильтр contains_species_common не применялся, когда species_common одновременно был фасетой; в выборку ошибочно попадало 1015 записей вместо 3. Устранено разделением применения фасетного выбора и текстового поиска: теперь они оба действуют совместно, без взаимного подавления. Во фронтенд CI старый тест Users ожидал v1.0.3 и падал только на литерале версии; он обновлён до 1.1.0. После исправления проверены 47 Python tests PASSED, 26 additional subtests PASSED, JavaScript syntax PASS, карта и MAX UI PASS, Docker PostgreSQL PASS.
Доработка после теста: разрешена серверная сортировка по ВСЕМ полям FIELDS, не только наиболее часто используемым; UI выпадающего списка перестроен на полную мета-схему сортировки.
