1. Цель
Реализовать полноценную административную загрузку ведомостей на тысячи деревьев/кустарников из CSV и XLSX с проверкой до записи. Массовый импорт разрешён только администратору; обычные пользователи и модераторы не должны иметь доступа даже при прямом HTTP-запросе. Старые положенные в SQLite данные не используются: основная PostgreSQL v0.7.0 остаётся единой базой.

2. Бэкенд
Создан import_api.py и PostgreSQL миграционный SQL inventory/schema_import_v100.sql. Таблица inventory_import_rows хранит результат разбора каждой строки, ошибки, исходный external_id, нормализованные поля и ID созданного объекта. Заголовок пакета inventory_import_batches хранит состояние uploaded/validated/importing/finished, число проверенных, импортированных и отклонённых строк, источник, дату.
API: POST /api/v2/admin/imports/preview — загрузка multipart файла (source + file), разбор UTF-8/UTF-8 BOM/Windows-1251 CSV и первого листа XLSX; GET /template — шаблон CSV; GET /{id} — просмотр результата порциями по 50 строк; GET /{id}/report.csv — полный CSV-отчёт; POST /{id}/commit — атомарное подтверждение подходящих строк; GET / — последние пакеты. Сервер проверяет роль admin через действующую авторизованную сессию.
Ограничения файла: 8 МБ, до 5000 строк и 40 столбцов. Координаты WGS84: широта 42–44, долгота 130–134. Импортируются только отдельные деревья и кустарники, не полигоны. Валидация проверяет экспертные поля (в том числе балл 1–6), реальные числовые диапазоны, наличие обязательных координат, согласованность источника, повтор external_id, занятый инвентарный номер и почти совпадающие существующие координаты/вид. Отсутствующий внешний ID создаётся детерминированным SHA-256 по типу, округлённым координатам и виду.
Предпросмотр не создаёт ни одного дерева. После явного подтверждения готовые строки добавляются в inventory_objects с source_type=bulk_import, статусом proposed, созданием inventory_basic, inventory_expert и inventory_audit. Весь пакет идёт в одной PostgreSQL-транзакции. При ошибке или новом конфликте весь набор откатывается, не оставляя частично внесённые объекты. Повторное подтверждение готового пакета запрещено.
Отчёт CSV содержит все строки с состоянием, внешним ID, породой, координатами, ошибками и созданным ID. Данные, начинающиеся с символов формулы Excel, экранируются апострофом, чтобы отчёт не запускал формулы при открытии в таблице.

3. Интерфейс
В ui/management.js добавлено окно «📥 Импорт Excel/CSV» только для роли admin. Есть скачивание шаблона, поле имени источника, выбор файла, отдельная кнопка проверки, итоги (готовые/ошибки/повторы), порционная таблица, скачивание полного отчёта и независимая кнопка «Подтвердить импорт». После успешного выполнения общая карта перечитывается. Гражданская форма дерева/кустарника сохранена.
Главная страница index.html показывает итоговую версию v1.0.0 справа сверху. В app.py подключены moderation_api, expert_api, import_api и health-версия 1.0.0. В requirements.txt установлен openpyxl для обработки XLSX. BOTHOST.md и inventory/RELEASE_V100.md описывают публикацию и работу интерфейсов.

4. Проблемы и решения
- Изначально клиентский отчёт предполагался только списком 50 строк. Это неудобно при тысячах записей: дополнительно создан endpoint полного CSV-отчёта и кнопка скачивания.
- Для входных идентификаторов и текстов отчёта предусмотрена нейтрализация формульных выражений Excel.
- Для предотвращения случайного дубля пакет явно разделён на предварительную проверку и подтверждение; вторая попытка завершения того же пакета возвращает 409.
- При создании длинного руководства в инструментарии возникла синтаксическая ошибка из-за необработанных markdown-разделителей в генераторе строки; файл репозитория не был создан. Текст руководства переписан, создание и чтение обратно выполнены успешно.
- Возможное ограничение больших HTTP-запросов BotHost учитывается ограничением 5000 строк и рекомендацией делить огромные ведомости на пакеты; отдельной фоновой очереди заданий пока нет.
- Инвентарные номера нормативного формата без исходных кадастровых сведений намеренно не генерируются.

5. Тестирование
tests/test_management.py на временной PostgreSQL 16 проверяет анонимные запросы (401), запрет импорта модератору (403), контроль колонок, неверные координаты, повторы external_id, Excel XLSX, CSV с разделителем ; и десятичной запятой, регистрацию профессиональных параметров, атомарное подтверждение, повторное подтверждение (409), отчёт CSV и его права доступа. Дополнительно успешно проверен импорт пакета ровно 1000 деревьев: 1000 готовых, 1000 подтверждённо внесённых в PostgreSQL, отчёт обновлён.
Итог CI на кандидате: 30 тестов PASSED, 17 дополнительных subtests PASSED; GitHub Actions сборки Docker с PostgreSQL — SUCCESS, проверка интерфейса — SUCCESS, проверка MAX UI — SUCCESS.
CI не использовал пользовательскую DATABASE_URL, реальную базу BotHost и реальный MAX; эти проверки остаются пользовательской приёмкой после обновления сервера.

7. Выпуск и следующий контроль
Все три этапа поставляются одной финальной версией v1.0.0. После завершения CI предполагается объединение PR №4 с main, без переноса секретов. Для применения нового API на BotHost нужно обновление из main с полной пересборкой Python Dockerfile. Заранее сохранённая переменная DATABASE_URL продолжает подключать PostgreSQL.
После запуска проверить GET /api/health (version=1.0.0), выдать своей учётной записи role=admin через защищённый pgAdmin/Adminer, проверить панель модерации, ввод эксперта, загрузку пробного CSV и отчёт. Инструкция: inventory/RELEASE_V100.md.
