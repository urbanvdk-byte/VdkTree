1. ИСХОДНАЯ НЕИСПРАВНОСТЬ
После сборки Python-образа v1.0.0 BotHost показывал «404 page not found», статус контейнера restarting. Из логов работы получено точное исключение:
  psycopg.errors.DatatypeMismatch: foreign key constraint "sessions_user_id_fkey" cannot be implemented
  DETAIL: Key columns "user_id" and "id" are of incompatible types: text and integer.
Падение возникало при импорте auth_backend.py → setup() → pgdb.py executescript(), то есть до запуска Uvicorn. Docker-сборка прошла успешно, но работающий HTTP-сервер не поднялся; 404 являлся следствием отсутствия запущенного приложения.

2. ПРИЧИНА
В базе PostgreSQL уже существовала таблица public.users с первичным ключом id INTEGER (или числовым типом), не соответствующим схеме VdkTree. Код auth_backend.py выполнял CREATE TABLE IF NOT EXISTS users (id TEXT ...) без указания схемы: PostgreSQL не создавал новую таблицу, поскольку public.users уже существовала. Затем команда CREATE TABLE sessions пыталась создать user_id TEXT REFERENCES users(id), где users.id INTEGER, и PostgreSQL отказал в объявлении внешнего ключа. Автоматические тесты прошлых версий работали на полностью пустой тестовой базе, поэтому не обнаружили конфликт общих имён таблиц.

3. ИСПРАВЛЕНИЕ v1.0.1
В pgdb.py создано строгое разделение пространства имён VdkTree:
- При первом подключении приложение автоматически выполняет CREATE SCHEMA IF NOT EXISTS vdktree в той же PostgreSQL DATABASE_URL.
- Создание схемы контролируется блокировкой threading.Lock; флаг готовности выставляется только после успешного COMMIT.
- Каждое рабочее соединение psycopg 3 устанавливает options="-c search_path=vdktree".
- В search_path НЕТ схемы public, поэтому незаключённые в кавычки имена users, sessions, login_limits, inventory_objects и всех остальных таблиц относятся только к vdktree.
- Существующие таблицы public.users и любые другие таблицы public не удаляются, не изменяются, не переименовываются, их данные остаются на месте.
- MAX-авторизация, роли, сессии, все растения, фотографии, импортные пакеты и аудит работают в одной отдельной схеме vdktree в прежней PostgreSQL DATABASE_URL.
- Новые переменные окружения, другой сервер БД, ручной SQL и удаление старой базы не требуются.
- Исправление доступно при условии, что роль PostgreSQL из DATABASE_URL имеет стандартное право CREATE SCHEMA в своей базе. Если нет, в логах будет отдельная ошибка permission denied, тогда требуется настройка прав роли в BotHost.

- app.py: версия FastAPI и /api/health поднята с 1.0.0 до 1.0.1.
- index.html: версия v1.0.1 отображается в правом верхнем углу сайта.
- Поведение карты, карточек, модерации, импорта и авторизации MAX не менялось.
- BOTHOST.md: добавлено описание схемы vdktree; ожидаемый ответ /api/health обновлён.

7. ПУБЛИКАЦИЯ И ПРИЁМКА
После успешного CI PR №5 объединяется в main. Для применения исправления пользователь выполняет «Обновить из Git» и полную пересборку BotHost из main с включённым Dockerfile. DATABASE_URL и MAX_BOT_TOKEN оставляются существующие.
Ожидаемые признаки: контейнер running (без restarting), Uvicorn слушает 0.0.0.0:3000; GET https://vdktree.bothost.tech/api/health возвращает ok=true, version=1.0.1, database=postgresql; домен / отображает VdkTree.
После первого входа через MAX администраторский запрос нужно выполнять к vdktree.users, не к public.users.
Если после обновления появится иной traceback, требуется прислать только логи работы, без токенов, паролей или DATABASE_URL.
