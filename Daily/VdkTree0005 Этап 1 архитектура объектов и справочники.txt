2. ФАЙЛЫ И СДЕЛАННОЕ
- inventory/catalog.json — справочник пяти типов: дерево, кустарник (точки); газон, цветник, природное сообщество (полигоны). Перечни полей базовой и экспертной карточки; 6 уровней санитарной оценки; категории газонов, цветников, природных сообществ; маркеры и статусы.
- inventory_model.py — независимые от сети правила прав: просмотр всех объектов; создание точек всеми ролями; создание площадных объектов модератором/админом; пользователь редактирует свою неподтверждённую точку первые 7×24 часа; модератор редактирует любую неподтверждённую точку, а подтверждённые редактирует только админ. Подтверждение вправе делать модератор или админ. Бэкенд и массовый импорт — только для админа. Замечания доступны всем авторизованным; закрывать их могут модераторы/админы.
- inventory_model.py — валидация координат Владивостока, GeoJSON Polygon/MultiPolygon, санитарной оценки, визуальной оценки, строк будущей импортной таблицы.
- inventory/schema_v050.sql — проект SQLite-модели объектов, основных полей, экспертных полей, площадных показателей, независимых замечаний, фото, истории изменений и журналирования массовых импортов. Схема НЕ ПРИМЕНЯЛАСЬ к работающей БД.
- inventory/import_template_v1.csv — шаблон учёта деревьев/кустарников с дополнительными координатами и external_id/import_source.
- inventory/ARCHITECTURE.md — архитектура, матрица полномочий, значения статусов, разделение быстрого и экспертного блоков, границы этапа и открытые вопросы.
- tests/test_inventory_model.py, tests/test_inventory_schema.py — тесты логики и структуры SQLite.
- index.html — только версия в правом верхнем углу изменена на v0.5.0 в feature-ветке.
- app.py — только номер версии FastAPI и /api/health изменён на 0.5.0 в feature-ветке.
- Создан draft PR #1 для запуска независимых тестов без слияния изменений в main.

3. СТАТУСЫ И ЗАМЕЧАНИЯ
- Дерево: неподтверждённое = серая точка; подтверждённое = зелёная.
- Кустарник: в обоих статусах голубая иконка; статус различается обводкой.
- Статус подтверждения не меняется автоматически от открытых замечаний.
- Красная точка «Требует уточнения» выводится поверх основной иконки, если имеется открытое замечание; все авторизованные пользователи могут их оставлять. Комментарии не дают права менять характеристики.
- Для площадных объектов режим подтверждения не был согласован, поэтому модель оставляет статус NULL, не придумывая новое значение.
- Пользователи видят все объекты карты независимо от подтверждения.

4. ОБНАРУЖЕННЫЕ ОШИБКИ И ИСПРАВЛЕНИЯ
- Первый прогон GitHub Actions для draft PR завершился ошибкой: тест обнаружил, что SQL CHECK принимает точечные записи без координат, поскольку в SQLite результат NULL при проверке CHECK не считается нарушением.
- Исправлено условие схемы: добавлены явные «lat IS NOT NULL AND lon IS NOT NULL» перед проверкой диапазона.
- После исправления запущены все проверки повторно: 18 тестов прошли, в том числе 17 subtests; Python compileall, Node --check и тесты MAX из предыдущего этапа — SUCCESS. Один не блокирующий warning из тестовых зависимостей Starlette/httpx.
- Вначале техническая попытка рассчитать SHA-256 резервной копии схемы ошиблась в JS-вычислении, до записи файлов; исправлен вспомогательный код, резервная копия создана и сверена. Производственный код не затронут.
