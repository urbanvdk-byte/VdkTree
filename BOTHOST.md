# VdkTree v1.1.1 — PostgreSQL на BotHost

VdkTree хранит MAX-пользователей, логины, сессии, деревья, кустарники, замечания, полигоны и фотографии **в одной PostgreSQL-базе**. SQLite больше не используется в работающем сервере.

**Исправление v1.0.1:** приложение автоматически создаёт отдельную схему PostgreSQL `vdktree` и работает только в ней. Это защищает от конфликта с ранее созданной `public.users`, где `id` может быть целым числом. Существующие таблицы `public` не удаляются и не меняются. Для выдачи роли администратора используйте `vdktree.users` (полные запросы — в `inventory/RELEASE_V100.md`).

## Переменные бота BotHost

- `DATABASE_URL` — полная строка PostgreSQL из раздела «Базы данных» BotHost, начиная с `postgresql://`. Её вводят в BotHost → бот VdkTree → «Переменные». **Не публикуйте пароль базы в GitHub, чате или логах.**
- `MAX_BOT_TOKEN` — существующий секрет бота MAX.
- `PORT` — BotHost выдаёт автоматически (по умолчанию 3000).
- `ALLOWED_ORIGINS` — необязательные дополнительные адреса фронтенда.

`DATA_DIR` можно оставить в настройках, но PostgreSQL-версия его **не использует для базы или фотографий**. Фото сохраняются в PostgreSQL как `BYTEA`.

## Обновление приложения

1. Оставить включённым «Использовать собственный Dockerfile».
2. Взять ветку `main` после объединения v1.0.1.
3. Сохранить переменные и выполнить полную пересборку/обновление из Git.
4. Посмотреть логи работы: приложение должно успешно подключиться к PostgreSQL и слушать `0.0.0.0:3000`.

**Предупреждение:** проект переключён на новую пустую PostgreSQL-базу, старые SQLite-данные автоматически не переносятся — это согласовано владельцем на этапе v1.0.1.

## Проверка

- `https://vdktree.bothost.tech/api/health` должен вернуть JSON с `ok:true`, `version:"1.1.1"`, `database:"postgresql"`.
- `https://vdktree.bothost.tech/api/v2/objects` должен вернуть `{"objects":[]}`, если база пока пустая.
- На карте и в реестре справа вверху должна быть версия `v1.1.1`.
- При открытии мини-приложения из чата `https://max.ru/id2540275814_1_bot` должна пройти серверная проверка подписи MAX; затем можно создать логин/пароль.
- Добавленное дерево должно быть видно на другом устройстве. Фото должно открываться по `/photos/{имя}` и оставаться после пересборки BotHost.

## Права

- Посетитель: публичная карта, без добавления/изменения.
- Пользователь: свои предложенные деревья/кустарники, редактирование до 7 суток, замечания ко всем объектам.
- Модератор: предложенные растения, свои площадные объекты, подтверждение и закрытие замечаний.
- Администратор: все данные и подтверждённые объекты. Панель массового импорта — следующий этап.

## Безопасность

Строка `DATABASE_URL` является секретом: не вставляйте в публичные файлы или скриншоты, не включайте подробные SQL-логи с параметрами. Проверки GitHub Actions используют **отдельную временную PostgreSQL-базу** с фиктивным паролем. Это не настоящая база BotHost.

## Функции v1.0.0

После обновления из main доступны: модераторская очередь, профессиональная карточка растений и площадей, административный импорт CSV/XLSX с предпросмотром, скачиваемым отчётом и отдельным подтверждением. Роли проверяются Python-сервером, все записи хранятся в PostgreSQL через DATABASE_URL.

Для проверки новых интерфейсов владелец должен один раз присвоить своей MAX-учётной записи роль admin через SQL-интерфейс PostgreSQL. По умолчанию каждому новому MAX-пользователю выдаётся роль user; автоматического назначения первого администратора нет (это защита от захвата управления).

Подробная инструкция и запросы для назначения ролей: inventory/RELEASE_V100.md.

Зависимости: openpyxl для XLSX, psycopg для PostgreSQL, FastAPI и Uvicorn. При полном обновлении с собственным Dockerfile зависимости устанавливаются по requirements.txt.

После обновления проверить GET /api/health → JSON версии 1.0.0 с database=postgresql. Проверить GET /api/v2/objects, затем роль модератора и предварительную проверку CSV без подтверждения записи.

## Повторный вход в обычный браузер через MAX — v1.0.2

Раньше кнопка «Проверить вход через MAX» работала только внутри мини-приложения MAX. Обычный браузер не получает подписанный `initData`, поэтому просто открыть/зарегистрироваться в MAX недостаточно для передачи сессии другому браузеру.

Теперь доступен защищённый вход по одноразовому коду:

1. На https://urbanvdk-byte.github.io/VdkTree/ нажмите «Войти» → «Войти через MAX по коду». Сайт покажет код из 8 символов, действующий 5 минут.
2. Откройте чат MAX-бота https://max.ru/id2540275814_1_bot и запустите **мини-приложение VdkTree** из чата.
3. В мини-приложении нажмите на профиль (кнопка с именем) и найдите блок «Подтвердить вход в браузере». Введите код с обычного сайта и подтвердите. Нужно открывать именно из MAX, чтобы поступили подлинные подписанные данные запуска.
4. Вернитесь в обычный браузер: он проверяет состояние каждые 2 секунды, после подтверждения получает свою сессию автоматически, без ввода пароля.

Код одноразовый. Одного открытия MAX-чата недостаточно — ввод и подтверждение кода обязательны. Если код истёк, запросите новый. Согласовывайте только вход на собственном устройстве и никогда не передавайте кому-либо код.

После подтверждения входа можно использовать логин/пароль как альтернативу. Для **нового пароля** минимальная длина теперь **8 символов**, максимальная 128. Имеющиеся пароли продолжат работать. Логин уникален в таблице `vdktree.users`: индекс `lower(login)` запрещает дубликаты, независимо от регистра. При проверке пароля его значение не хранится открытым текстом: сервер сравнивает scrypt-хеш с солью. Логины 4–32 символа: латинские буквы, цифры, подчёркивание и дефис.

Браузерные и MAX-сессии хранятся отдельно, срок действия — 7 дней. Текущая реализация обычного браузера использует sessionStorage: закрытие вкладки/браузера может потребовать нового входа.

## Обновление BotHost для v1.0.2
Обновить код бота из `main` и пересобрать собственный Dockerfile. Секреты `DATABASE_URL` и `MAX_BOT_TOKEN` менять не требуется. В `/api/health` ожидается версия `1.0.2`. Полный сценарий подтверждения через реальный MAX нужно проверить вручную после обновления.


## Администрирование пользователей v1.0.3

Новая кнопка «👥 Пользователи» доступна только роли admin. В разделе администратор ищет зарегистрированных участников, назначает роли, блокирует/разблокирует, завершает сеансы, сбрасывает логин/пароль и просматривает журнал действий. Вся проверка прав выполняется сервером Python.

По прямой команде владельца при **первом запуске v1.0.3** миграция проверяет уже существующий логин savenko в таблице vdktree.users. Если пользователь найден и не заблокирован, назначается роль admin и пишется аудит. Результат сохраняется один раз в vdktree.admin_bootstrap_history, поэтому новый savenko, зарегистрированный после миграции, не получит права автоматически. Повторный перезапуск не вернёт роль, если её отозвали.

Откройте админку после обновления BotHost из main, проверив /api/health (version 1.0.3). Если интерфейс остался с ролью user, заново войдите/обновите страницу и проверьте результат миграции, как описано в inventory/USERS_V103.md. PostgreSQL пароль и DATABASE_URL не нужно отправлять в чат.

Важно: ранее в документации admin требовалось назначать вручную. С v1.0.3 только назначение существующего savenko выполняется один раз при первом старте; все дальнейшие изменения — через панель или SQL владельца.


## Отдельный реестр деревьев — v1.1.0

В дополнение к публичной карте и админским инструментам появилась отдельная страница https://urbanvdk-byte.github.io/VdkTree/registry.html. В BotHost также открывается /registry или /registry.html. На карте сверху есть ссылка «📋 Реестр деревьев».

В реестре доступны все серверные деревья/кустарники из PostgreSQL, включая неподтверждённые. Есть фильтры по полям (галочки с динамическими счётчиками, диапазоны, текст, даты), совмещение нескольких фильтров, сортировка по всем характеристикам, пагинация, выбираемые колонки, просмотр профессиональной карточки. Администратор может там же редактировать поля и инвентарный номер.

Для каждого растения/кустарника открыта выгрузка индивидуальной Excel-ведомости Приложения № 2, таблицы 2.4 предоставленного регламента, с дополнительной вкладкой по §5.4. Ведомость содержит только известные данные: отсутствие измерений остаётся пустым. Графа «Х/У/Н» не выводится автоматически из санитарного балла 1–6, поскольку регламент не содержит их точного соответствия. Выписка не является заверенным муниципальным паспортом.

Старые локальные «демометки» из browser localStorage (vdktree-demo-v020) больше не рисуются на карте, однако содержимое хранилища пользователя не уничтожается. Все существующие объекты PostgreSQL и MAX-пользователи сохранены.

После обновления BotHost из main и полной пересборки проверьте https://vdktree.bothost.tech/api/health → version=1.1.0, откройте /registry, примените фильтры и скачайте ведомость. Никакие изменения DATABASE_URL или MAX_BOT_TOKEN не нужны. Полное руководство: inventory/REGISTRY_V110.md.


## v1.1.1 — исправление перехода, локальных демометок и масштаба

- Ссылка «← Карта» на странице реестра теперь указывает на `./?v=1.1.1`, а не `./index.html`. Это работает и на GitHub Pages в папке /VdkTree/, и на BotHost в корне домена.
- Сам BotHost дополнительно обслуживает `/index.html` как алиас `/` — старые прямые ссылки больше не дают `{"detail":"Not Found"}`.
- Оба HTML-маршрута BotHost имеют заголовок `Cache-Control: no-store, must-revalidate`. Локальные файлы JS/CSS на карте и в реестре подключены с параметром `?v=1.1.1` для устранения кэшированной старой версии JavaScript.
- Устаревший локальный ключ браузера `vdktree-demo-v020` при открытии карты **переносится в `vdktree-local-demo-archive-v111`**: исходный ключ удаляется только после проверки сохранённой копии, данные не теряются. Метки старой демоверсии не создаются и никогда не отправляются в PostgreSQL.
- Кнопки масштаба Leaflet теперь внизу слева, вне верхней панели фильтра. Настройка применяется на телефонах и настольных браузерах.
- После обновления BotHost из main / полной пересборки проверяются `/api/health` (версия 1.1.1), `/`, `/index.html`, `/registry`, переход из реестра в карту, отсутствие локального демомаркера и работа +/-.

Подробности: `inventory/MAP_FIX_V111.md`; дневник: `Daily/VdkTree0019 ... .txt`.
