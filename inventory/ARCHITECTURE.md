# VdkTree — этап 1: архитектура данных и справочники (v0.5.0)

Источник: «Регламент инвентаризации, цифрового учета и мониторинга зеленых насаждений и природных сообществ города Владивостока», прежде всего раздел 5 и приложения № 2, таблицы 2.3–2.5. Сервисные правила ролей, статусов и замечаний — решения владельца VdkTree в обсуждении от 05.11.2026; они **не являются утверждениями самого регламента**.

## Устройство системы
- **Публичный фронтенд** (GitHub Pages): видят всё, что внесено на карту, включая непроверенные объекты. Пользователи добавляют деревья/кустарники, оставляют замечания и могут редактировать собственные непроверенные точки первые 168 часов.
- **Расширенный режим того же фронтенда для модератора**: добавление площадных объектов, редактирование/подтверждение любых непроверенных деревьев и кустарников, рассмотрение замечаний. **Нет доступа к административному бэкенду**.
- **Административный бэкенд** (BotHost): полный доступ только администратору, в том числе массовый импорт таблиц, изменение подтверждённых записей и управление пользователями.
- Авторизация: сначала через MAX, затем добровольный логин/пароль; единая учётная запись.
- Данные хранятся на BotHost. Текущий `app.py` и `trees.sqlite3` — раннее MVP; `inventory/schema_v050.sql` — **проект новой схемы**, пока никуда не применён.

## Геометрия и объекты

| Тип | Геометрия | Кто добавляет | Как показываем |
| --- | --- | --- | --- |
| Дерево `tree` | Точка | Все вошедшие | Серый, если «Предложено»; зелёный, если «Произрастает» |
| Кустарник `shrub` | Точка | Все вошедшие | Голубая иконка в обоих случаях; контур отличает подтверждение |
| Газон `lawn` | Полигон | Модератор/админ | Площадной слой |
| Цветник `flowerbed` | Полигон | Модератор/админ | Площадной слой |
| Природное сообщество `natural_community` | Полигон | Модератор/админ | Площадной слой |

**Основной статус дерева/кустарника:** `proposed` («Предложено»), `confirmed` («Произрастает»). Подтверждают модератор или администратор. Администратор может редактировать подтверждённое дерево без повторной модерации: основной статус остаётся `confirmed`. Для площадных объектов основные статусы ещё не согласованы, поэтому схема хранит `NULL` до утверждения механизма.

**Замечания:** независимая таблица `inventory_clarifications`. Любой авторизованный пользователь может оставить текстовое замечание на любом объекте. Пока есть хотя бы одно открытое замечание, на соответствующей точке появляется красный кружок. Он **не меняет** основной статус и не даёт автору замечания права редактировать объект. Закрыть замечание могут модератор или администратор; сохраняются автор, даты и результат рассмотрения.

## Два блока карточки

**А. Общий (быстрый):** координата на карте, фотографии, название растения («не знаю» допустимо), примерная высота по диапазонам, примерная толщина ствола (необязательно), внешнее состояние («выглядит здоровым / повреждено / засохло / не знаю»), видимые повреждения, дата наблюдения, комментарий. Система проставляет ID, автора, время создания. Общая визуальная оценка **не равна** экспертной шестибалльной санитарной шкале.

**Б. Экспертный:** № участка/биогруппы/растения, тип насаждения, жизненная форма, ботанический вид, количество, диаметр на высоте 1,3 м, высота, возраст, санитарное состояние по шкале 1–6, категория усыхания, дефекты, рекомендации по уходу; для Владивостока также противоэрозионная функция, наклон ствола, асимметрия кроны, сведения об эндемиках и реликтах. Это соответствует показателям раздела 5 и ведомости 2.4.

**Для площадных объектов:** газон — площадь, тип (обыкновенный, луговой, партерный, на откосе, инертный), состояние; цветник — площади по однолетникам, многолетникам, луковичным, розам, смешанным; природное сообщество — тип (лесное, луговое, околоводное) и контур/площадь.

## Матрица прав (ограничения выполняет будущий сервер)

| Действие | Пользователь | Модератор | Администратор |
| --- | --- | --- | --- |
| Читать все объекты | Да | Да | Да |
| Создать точку (дерево/куст) | Да | Да | Да |
| Редактировать собственную непроверенную точку | Только первые 168 часов | Да | Да |
| Редактировать чужую непроверенную точку | Нет | Да | Да |
| Редактировать подтверждённую точку | Нет | Нет | Да |
| Подтверждать непроверенную точку | Нет | Да | Да |
| Создавать полигоны | Нет | Да | Да |
| Редактировать полигоны | Нет | **Свои** (временное консервативное правило) | Любые |
| Оставить замечание | Да | Да | Да |
| Закрыть замечание | Нет | Да | Да |
| Массовый импорт | Нет | Нет | Да |
| Доступ к административному бэкенду | Нет | Нет | Да |

**Открытый вопрос:** разрешить ли модераторам редактировать чужие полигоны? До решения даём им право редактировать только свои, не расширяя доступ по умолчанию.

## Массовый импорт — подготовка
- `inventory/import_template_v1.csv` — заголовки таблицы подеревного учёта 2.4 с добавленными **обязательными** координатами `latitude`, `longitude`.
- Импортируются `tree`/`shrub` как отдельные точки. Для полигонов будет отдельный геопространственный формат.
- `external_id` + `import_source` для поиска повторов; обязательная предварительная проверка, отчёт ошибок по строкам, подтверждение администратором до сохранения.
- Регламентная нумерация `VL-ДД.ММ.ГГГГ-ХХХ` зависит от кадастровых данных; мы храним её как **опциональный** `inventory_number` и не генерируем фиктивные номера.
- Импортированные записи по умолчанию `proposed`, подтверждение — отдельное действие. Это консервативное проектное решение, пока не согласован особый порядок приёма профессиональных ведомостей.
- Схема `inventory_import_batches` готова для будущего фонового пакетного импорта; сам интерфейс загрузки будет на этапе 5.

## Границы реализации этапа 1
Реализованы **справочник, проект схемы, чистые функции валидации/проверки прав и тесты**. Новая модель **не подключена к работающим API**, данные действующей карты не мигрированы. Старый MAX-вход и BotHost не должны быть затронуты. Следующий этап — интерфейс точки/кустарника и форма из блока А, с сохранением на сервере после отдельной безопасной миграции.

## Справочные файлы
- `inventory/catalog.json` — поля, типы, цветовые правила, нормативные шкалы.
- `inventory_model.py` — проверки точек/полигонов и прав.
- `inventory/schema_v050.sql` — схема для будущей базы BotHost; не исполнять в боевой базе без миграционного плана.
- `inventory/import_template_v1.csv` — шаблон CSV (UTF-8 с BOM опционально).
- `tests/test_inventory_model.py` — автотесты.
