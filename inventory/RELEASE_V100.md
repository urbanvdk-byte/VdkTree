## Что реализовано
v0.8.0 — панель модератора. Очередь предложенных деревьев и кустарников, фильтры по задачам и типам, счётчики, открытие карточки, подтверждение, возврат на уточнение с комментарием и история всех решений. Замечания сохраняются независимо от статуса объекта.

v0.9.0 — профессиональная карточка. Редактирование экспертных показателей деревьев и кустарников, включая номер участка, биогруппу, номер растения, тип посадки, жизненную форму, ботанический вид, количество, диаметр ствола на высоте 1,3 м, высоту, возраст, санитарное состояние 1–6, категорию усыхания, дефекты, рекомендации по уходу, противоэрозионную функцию, наклон, асимметрию кроны, эндемичность/реликтовость. Для площадных объектов — типы, состояние и параметры площади. Данные видны любому посетителю, изменение разрешено только модератору с подходящими правами или администратору.

v1.0.0 — импорт CSV/XLSX. Только администратор загружает файл и задаёт имя источника. Сначала создаётся предварительный отчёт с разбором ошибок и повторами, без добавления растений. Затем отдельным подтверждением подходящие строки атомарно записываются в PostgreSQL. Отчёт доступен для скачивания в CSV. Ошибочные и повторные строки не импортируются.

## Как получить роль администратора для проверки
Все новые MAX-пользователи по умолчанию получают роль user. Это намеренная защита: первый посетитель не становится администратором автоматически. После первого входа через MAX откройте pgAdmin базы PostgreSQL VdkTree в BotHost (ссылка «Открыть в Adminer» или pgAdmin в панели БД).

Выполните запрос для просмотра только идентификаторов:
SELECT id,max_id,display_name,role FROM users ORDER BY created_at DESC;

Сверьте свою запись по max_id. Затем назначьте роль, подставив собственный идентификатор вместо ВАШ_MAX_ID:
UPDATE users SET role='admin' WHERE max_id='ВАШ_MAX_ID' RETURNING max_id,display_name,role;

Для назначения модератора другому зарегистрированному участнику используйте:
UPDATE users SET role='moderator' WHERE max_id='MAX_ID_УЧАСТНИКА' RETURNING max_id,display_name,role;

Обновите страницу карты — появятся кнопки «🛡️ Модерация» и (только для admin) «📥 Импорт Excel/CSV». Никогда не публикуйте реальные DATABASE_URL, MAX_BOT_TOKEN или пароль базы.

## Как проверять модерацию
1. Войдите ролью moderator/admin и откройте «🛡️ Модерация» в правой части карты.
2. Выберите тип задачи: вся очередь, предложенные растения или открытые замечания; при необходимости тип объекта.
3. Нажмите «Карточка», чтобы изменить базовые сведения. Внутри можно закрывать замечания с результатом.
4. Нажмите «✅ Подтвердить» после проверки сведений — растение станет зелёным (для кустарника голубая точка с другой обводкой).
5. Если нужны сведения автора, нажмите «↩ На уточнение», напишите объяснение. Статус останется «Предложено», на карте появится красное замечание.
6. Нажмите «История решений» — там записываются подтверждения, уточнения, правки и другие действия.

Модератор изменяет только неподтверждённые растения и собственные площадные объекты; администратор может редактировать подтверждённые растения и любые площадные объекты.

## Как проверять профессиональную карточку
1. Откройте на карте существующее дерево или кустарник.
2. Найдите раздел «Профессиональные сведения».
3. Под допустимой ролью нажмите «Заполнить экспертные данные».
4. Введите реальные экспертные измерения (диаметр на высоте 1,3 м в сантиметрах, высоту в метрах, возраст в годах, санитарный балл от 1 до 6).
5. Неизвестные поля можно оставить пустыми. Сохранение экспертной части не сбрасывает основной статус подтверждения.
6. Убедитесь, что значения видны после обновления страницы.

Для газона, цветника и природного сообщества редактируется отдельная карточка площади, типа, состояния и состава посадок.

## Как проверить массовую загрузку
1. Войдите как администратор → «📥 Импорт Excel/CSV».
2. Скачайте шаблон CSV. Допустимые форматы: CSV в UTF-8, UTF-8 BOM или Windows-1251, а также XLSX (первый лист).
3. В каждой строке укажите latitude, longitude, тип tree/shrub, породу и другие известные показатели. Если external_id отсутствует, система сформирует повторяемый ID по типу, координатам и виду.
4. Задайте имя источника импорта над файлом. Если в строках заполнен столбец import_source, он должен совпадать с этим именем.
5. Нажмите «Проверить файл». Ошибки координат, неприемлемые экспертные баллы, повторные external_id, инвентарные номера и практически совпадающие объекты будут показаны в отчёте.
6. Нажмите «Скачать отчёт CSV», чтобы получить полную таблицу результатов, включая номера строк.
7. Только после проверки нажмите «Подтвердить импорт». Подходящие записи появятся на общей карте со статусом «Предложено».
8. Повторное подтверждение того же пакета не допускается; повторная загрузка того же источника обнаружит дубликаты.

Ограничения одного файла: до 8 МБ, 5000 строк, 40 столбцов. Для больших ведомостей используйте несколько пакетов. Тесты проверили одно подтверждение пакета 1000 растений. Поддерживаются деревья и кустарники; GIS-импорт полигонов не входит в этот выпуск. Ведомственные инвентарные номера не генерируются без исходных кадастровых данных.

## Развертывание на BotHost
Новые маршруты API расположены на Python-сервере, поэтому необходимо обновить код BotHost из main и пересобрать контейнер с собственным Dockerfile. DATABASE_URL и MAX_BOT_TOKEN остаются в секретных переменных бота.

Проверка после обновления:
https://vdktree.bothost.tech/api/health
Ожидаемый результат: ok=true, version=1.0.0, database=postgresql.

Автоматические тесты используют отдельную временную PostgreSQL 16, не настоящую базу. Реальный вход MAX и тест с разных устройств выполняются при приёмке пользователем.
