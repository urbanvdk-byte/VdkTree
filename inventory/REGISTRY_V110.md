# VdkTree v1.1.0 — профессиональный реестр деревьев и кустарников

Дата: 08.11.2026
Сайт реестра: https://urbanvdk-byte.github.io/VdkTree/registry.html
Общая карта: https://urbanvdk-byte.github.io/VdkTree/
BotHost: https://vdktree.bothost.tech

## 1. Почему пропала «локальная демозапись»

До версии v1.1.0 ui/map.js рисовал отдельные **локальные демометки** из browser localStorage по ключу vdktree-demo-v020. Это след старого MVP VdkTree; такие записи не были сохранены в PostgreSQL, не были доступны другим пользователям и не могли участвовать в государственном подеревном учёте. На сервере этих записей нет.

В v1.1.0 отключено **только отображение** этого старого слоя. Поскольку пользователь мог сохранять старую информацию в своём браузере, запись localStorage не очищается принудительно. Реальные записи PostgreSQL — деревья, кустарники, фото, замечания — не изменены. Если нужна миграция старых локальных данных, её можно выполнить отдельно после анализа.

## 2. Отдельный табличный реестр

На карте вверху есть ссылка «📋 Реестр деревьев», открывающая registry.html. Сервис BotHost также поддерживает /registry или /registry.html. Реестр является отдельным публичным интерфейсом, а не таблицей внутри карты; любой посетитель может просматривать данные без MAX-авторизации.

В реестр входят **все деревья и кустарники** из inventory_objects / inventory_basic / inventory_expert в PostgreSQL: подтверждённые и предложенные. Газоны, цветники и природные сообщества в этом разделе не показываются — у них собственные таблицы регламента 2.3 и 2.5, это отдельный будущий раздел. Реестр использует серверную пагинацию (по 50 записей, максимум 100 для API) без ограничения картографического API в 5000 объектов.

## 3. Поиск и фильтрация по принципу каталога DNS

Вдохновение — каталожный поиск DNS, где можно совмещать несколько групп фильтров и диапазоны технических характеристик. Не копируется оформление или программный код DNS.

- Левая панель разделена на блоки «Учёт», «Местоположение», «Вид и посадка», «Размеры и возраст», «Состояние», «Специфика Владивостока».
- Поиск по названию породы, ботаническому виду, инвентарному номеру, ID, номеру участка, номеру биогруппы, номеру растения и комментарию.
- Галочки для типа дерева/кустарника, статуса, видимой оценки, шестибалльного санитарного состояния, источника, некоторых видов/участков, противоэрозионной функции и эндемичности; в каждой фасете видны счётчики. Можно выбирать несколько вариантов.
- Для числовых характеристик — диапазоны «От»/«До»: высота, возраст, диаметр на 1,3 м, приблизительный диаметр, количество, наклон, широта, долгота и количество фотографий.
- Для дат — диапазоны: наблюдение, создание, обновление, подтверждение.
- Для остальных хранимых текстовых параметров — фильтр «Содержит»: тип посадки, жизненная форма, дефекты, рекомендации, заметки, номера, источник импорта, внешний ID и др.
- Фильтры работают совместно (AND между полями, OR внутри множества галочек одного поля). Выбранные условия показываются как удаляемые «чипы». Кнопка «Сбросить» очищает всю выборку.
- При изменении других фильтров фасетные счётчики обновляются.
- Сортировка по ключевым колонкам, в обе стороны, а также кликом по заголовкам таблицы.
- Пользователь может включать и скрывать основные столбцы таблицы. Выбор запоминается в localStorage как **настройка отображения**, не меняющая серверные данные.
- Сайт адаптирован для мобильного телефона: панель фильтров выдвигается, основная таблица прокручивается по горизонтали.

## 4. Профессиональная карточка

Нажатие на строку открывает карточку со всеми сохранёнными данными. Отдельно показываются:
1) Общие сведения — ID, инвентарный номер, тип, порода, источник, статус, координаты, дата наблюдения, визуальная оценка.
2) Подеревный учёт по таблице 2.4 — номер участка, биогруппы и растения, тип насаждения, жизненная форма, ботанический вид, количество, диаметр, высота, возраст, санитарный балл 1–6, категория усыхания, дефекты, рекомендации.
3) Владивостокские особенности из пункта 5.4 — противоэрозионная/берегозащитная функция, наклон ствола, асимметрия кроны, эндемик/реликт.
4) Фотографии и замечания, если они имеются.

**Администратор** после входа через MAX или пароль может изменить основные сведения, инвентарный номер и все профессиональные поля. Они сохраняются в действующих API PostgreSQL; история экспертных правок пишется в inventory_audit. Изменение роли/статуса подтверждения происходит отдельной модераторской операцией, чтобы не смешивать инвентаризацию и подтверждение наблюдений. Обычные посетители не получают кнопок редактирования, и сервер проверяет права независимо от интерфейса.

## 5. Индивидуальная заполненная ведомость из регламента

У каждой записи есть публичная кнопка «↓ Скачать ведомость 2.4 (Excel)».

Источник — предоставленный владельцем файл «Регламент инвентаризации, цифрового учета и мониторинга зеленых насаждений города Владивостока.docx», **Приложение № 2, таблица 2.4**, и требования пункта 5.4 и 5.5. Формат: редактируемый XLSX, один файл на дерево/кустарник.

Первый лист «Ведомость 2.4» повторяет **13 граф** ведомости:
1. № участка
2. № биогруппы
3. № растения
4. Тип насаждения
5. Жизненная форма
6. Вид растения
7. Количество (шт.)
8. Диаметр ствола на высоте 1,3 м (см)
9. Высота (м)
10. Возраст (лет)
11. Состояние Х/У/Н
12. Категория усыхания / дефекты
13. Рекомендации

В строку помещаются **только реально сохранённые** в PostgreSQL значения. Если есть лишь русское название породы и нет ботанического вида, используется русское название, а не выдуманная латынь.

Важно: в заголовке таблицы 2.4 стоит «Сост. Х/У/Н», а пункт 5.5 требует отдельную оценку по шестибалльной шкале. Автоматическое соответствие между ними документом не задано. Поэтому графа Х/У/Н остаётся **пустой**, пока не будет отдельного достоверного значения. Санитарный балл 1–6 и его точная расшифровка содержатся на втором листе «Доп. сведения». Это не ошибка заполнения, а предотвращение ложной экспертизы.

Второй лист содержит подтверждённые цифровые и дополнительные данные: ID, необязательный инвентарный номер, породу, санитарный балл, противоэрозионную функцию, наклон, асимметрию, эндемичность, координаты, источник и дату. Отсутствующие значения остаются пустыми. Тексты, начинающиеся с формульных символов Excel, экранируются для безопасности.

Скачиваемый файл является **рабочей индивидуальной выпиской из VdkTree, не заверенным паспортом или муниципальным актом**; подписи, кадастровые данные и официальное согласование не подставляются автоматически. Регламентный инвентарный номер VL-ДД.ММ.ГГГГ-ХХХ не генерируется без кадастровой информации.

## 6. Развертывание и проверка

1. После слияния PR с main обновить BotHost из main с полной пересборкой собственного Dockerfile.
2. Проверить https://vdktree.bothost.tech/api/health → version 1.1.0 и database postgresql.
3. Открыть карту; старая «локальная демозапись» больше не должна показываться.
4. Нажать «📋 Реестр деревьев». Проверить наличие реальных серверных деревьев/кустарников и число записей.
5. Задать одновременно вид дерева, диапазон высоты, санитарный балл, номер участка; проверить изменяющийся список и счётчики.
6. Открыть строку, прочитать профессиональную карточку и скачать XLSX. Убедиться, что неизвестные измерения в XLSX пустые.
7. Войти как admin, изменить экспертную характеристику, проверить её после обновления и повторно скачать ведомость — новое значение должно попасть в XLSX.
8. Убедиться, что обычный пользователь и аноним не могут менять инвентарный номер/экспертные данные.
