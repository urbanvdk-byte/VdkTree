# VdkTree v1.1.1 — исправления карты и перехода из реестра
Дата: 08.11.2026
Репозиторий: urbanvdk-byte/VdkTree

## Исходные ошибки
1. Кнопка «← Карта» в registry.html указывала на ./index.html. На GitHub Pages такой файл существует, но на BotHost FastAPI прежде обслуживал карту только по /. По этой причине BotHost /index.html возвращал {"detail":"Not Found"} (404).
2. На карте снова показывалась «Локальная демозапись», хотя предыдущий релиз удалил создание таких меток в ui/map.js. Источник исходных меток был в старом клиентском localStorage, ключ vdktree-demo-v020. Актуальный код v1.1.0 не рисует эти метки. Наиболее вероятная причина повторного появления — закешированная старая страница/JS либо не обновлённый BotHost. Без доступа к конкретному устройству нельзя достоверно установить, где находился кеш.
3. По умолчанию Leaflet ставил +/- слева сверху, а фильтр объектов поверх него. На пользовательском скриншоте видно перекрытие верхнего левого края карты.

## Реализовано v1.1.1

### Ссылка на карту и маршрутизация
- Кнопка «← Карта» теперь ведёт на ./?v=1.1.1. В GitHub Pages это /VdkTree/?v=1.1.1, в BotHost — /?v=1.1.1.
- В app.py появился алиас /index.html для /: обе ссылки возвращают index.html.
- На серверные HTML-ответы /, /index.html, /registry, /registry.html добавлен Cache-Control: no-store, must-revalidate.
- Старые прямые ссылки на /index.html не должны давать 404.

### Архивирование старых демоданных
- Перед выводом карты новый ui/map.js ищет старый браузерный ключ vdktree-demo-v020.
- Если ключ есть, значение копируется в vdktree-local-demo-archive-v111, проверяется равенство архивной копии и лишь затем удаляется старый ключ.
- При ошибке localStorage данные не удаляются. Архив сохраняется только локально на том же устройстве и может потребоваться при отдельной миграции. Данные не отправляются в PostgreSQL.
- Новый код карты показывает исключительно объекты из PostgreSQL. Старые клиентские демометки не рисуются, их устаревший стиль тоже удалён.
- Все собственные JS/CSS-ресурсы карты и реестра подключаются с ?v=1.1.1, чтобы свежий HTML не использовал прежние закешированные файлы.

### Кнопки масштаба
- Встроенный верхнелевый zoomControl Leaflet отключён, создан отдельный L.control.zoom({position:"bottomleft"}).
- Кнопки +/- располагаются снизу слева с отступом 12 px от левого края и 22 px снизу.
- Кнопки 35x35 px удобны и на сенсорном экране. Фильтр остаётся сверху, без перекрытия zoom.

## Проверка на сайте после обновления
1. После объединения PR обновить BotHost из main и выполнить полную пересборку.
2. Убедиться, что https://vdktree.bothost.tech/api/health показывает version 1.1.1 и database postgresql.
3. Открыть https://urbanvdk-byte.github.io/VdkTree/?v=1.1.1 и https://urbanvdk-byte.github.io/VdkTree/registry.html?v=1.1.1 — верхний правый угол должен показывать v1.1.1.
4. На https://vdktree.bothost.tech/registry нажать «← Карта». Проверить открытие карты без 404. Проверить /index.html как отдельный маршрут BotHost.
5. Убедиться, что демометки старой версии больше не показываются; реальные деревья и кустарники сохраняются.
6. На телефоне и компьютере проверить +/- в левом нижнем углу.
7. Если браузер показывает старую страницу, открыть URL с ?v=1.1.1, выполнить обновление без кеша. На BotHost необходимо обновление контейнера, иначе сам сервер продолжит отдавать старую версию.

## Защита и тесты
Не изменялись PostgreSQL-схемы, данные деревьев и пользователей, MAX-вход и токены, права, инвентарные ведомости и FlClashX. Секретных переменных не добавлено.
Доработаны tests/test_map_ui.js, tests/test_registry_ui.js, tests/test_users_ui.js, tests/test_registry.py и Docker smoke test. Проверяются ссылки и маршруты карты/реестра, кэширование HTML, метки и архив, расположение zoom и версия.
Резервные копии каждого изменяемого файла созданы в /backups и проверены до замены. История реализации: Daily/VdkTree0019 Исправление карты демометки и масштаба.txt.
